# [アプリ名]
## 1. サービス概要

このアプリは抑うつ・うつ病・適応障害の方が、症状を記録するジャーナリングアプリです。
ユーザーが記録を蓄積すると、5分の診察で伝えられるようにAIが病状を整理します。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

きっかけは私自身抑うつ状態で休職したことです。
その際、自分の状態を客観的に評価し、5分程度の短い診察時間で主治医に伝えることが難しく感じられました。
復職がプレッシャーとなり自分の状態を恣意的に解釈し、症状を過小評価していた可能性もあります。
「客観的な存在が私のデータを整理・評価してくれたら診察がもっと楽になる」と感じたところからこのサービスが生まれました。

### 2-2. なぜそれが「気になった」のか

- 主治医に対して病状を整理して正確に伝えるために役立つツールがあれば良いなと思いました。
- 療養には月単位で時間がかかり、時間が経っても良くなっている実感が伴わないため、目に見える記録が欲しいと思いました。
- 紙のジャーナリングも1年間しましたが、構造化されておらず変化が分かりにくいと思いました。
- 病状を客観視し、自分で判断するプレッシャーをなくしたいと思いました。
- AIメンタルケアに興味をもち、AIによる評価を判断材料の一つとして取り入れたいと思いました。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

診察でうまく症状を伝えられず、終わった後でモヤモヤする。

### 3-2. 本当に解決したい課題は何か

- 診察では、自分が主観的に重要だと思っている内容を伝えることが多い。
- 主治医が理解してくれなかったり、期待しているアドバイスをくれなかったりする。
- 患者自身が、自分の症状を客観的に理解できていない。

→ 本当に解決したい課題：症状を客観視できるようになること。

※「アプリでできそうなこと」ではなく
※「人の行動・感情の問題」になっているか確認してください。

- 「死にたい」のトリセツ
  苦しさの共感に焦点を当てており、具体的な療養のイメージがつかめない点が不満点。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Rails 7.2
- 言語：Ruby 3.2
- DB：PostgreSQL（Neon）
- デプロイ先：Render
- 使用予定ライブラリ：
  ‐ フロントエンド：Hotwire（Turbo / Stimulus）/Chart.js
  - 認証：devise/OmniAuth
  - CSSフレームワーク：Bootstrap
  - テスト：RSpec/Rubocop
  - Web API：OpenAI API

### 10-2. 技術選定の理由

- なぜこの技術を使うのか：
  ユーザー認証必須のため、OmniAuthで多様な認証手段を用意します。
  MVCアーキテクチャの効率的な開発のためRails7系を採用します。シンプルな機能のためフロントは分離しません。
  洗練されたフロントになるよう、AI整理の非同期表示やChart.jsによるグラフ表示を取り入れます。
  自然言語処理のためOpenAI APIを採用します。
- 今回チャレンジしたい点：
  使いやすいUIにこだわる。
- 不安な点：
  データが増えた場合にAIの回答を非同期で表示する速度。
