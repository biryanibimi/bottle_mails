# bottle_mails
## 1. サービス概要

アナログで温かな「ボトルメール」を通じて、うつ状態と戦う人の苦しみを少しでも軽くします。匿名でメッセージを流したり、誰かからメッセージや返信が届いたり。「苦しみを知ってもらえた」「自分だけじゃないんだ」と気持ちがふわっと軽くなる瞬間が生まれます。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

私は2024年うつ状態で休職し、実家で療養していました。家族が働いている間、私はただ寝ているだけで何もできませんでした。なぜこうなったかを延々と考えながら、辛い記憶を芋づる式に思い出しては自分を責め、言い表せない苦しい思いをしました。仕事で疲れている家族のことは煩わせたくないと思いながらも、抱えきれない苦しみを家族に吐き出してしまいがちでした。重く苦しい内容を聞くことは、家族にとっても疲弊する原因となります。結果的に療養中は家族と衝突することが増え、そのせいでまた自分を責めました。

昨今はAIが進化し、AIに対して感情を吐き出すことが一般化しました。ですが、その返信は「AI構文」とも揶揄されるようにパターン化され、過度にユーザーの感情を汲み取るような主観的な内容が含まれます。苦しみを手放して俯瞰するのに最適な手段とは言えません。また、うつ状態による休養期間は最低数か月と長く、その大部分を一人で苦しみながら過ごすことになります。ユーザーはAIを活用しながらも、時に人の温かみを渇望することがあるはずです。

そんな時に苦しみを吐き出せる場として寄り添うのが本アプリです。安全性に配慮した設計で、脳の疲労が著しい時にも利用できるシンプルな操作を意識しています。苦しい感情や思考を切り離して心を軽くすると共に、自分の苦しみを誰かに受け止めてもらったり、誰かの苦しみを知って自分の苦しみを見つめなおすことができます。ボトルメールというアナログな概念を通して、まるで本当にメッセージが流れ着いているかのような温かみのある体験を提供します。

### 2-2. なぜそれが「気になった」のか

私は人から言われたことを真面目に受け止めて自責しやすい性格です。うつ状態から寛解して2年経ち、多くの学習や経験を経て少しずつ自責をやめることができています。うつ状態から立ち直る確実な手段は存在せず、長い時間をかけてゆっくりと疲労を取っていくことが肝要です。自らの療養経験を通じて、誰かの長い休息時間に寄り添ってあげたいと強く感じました。

症状や本人が抱える問題は必ずしも家族や友人が十分に理解できるとは限らず、そもそも親しい人に話して迷惑をかけたくないと思う人もいます。症状を理解している人同士で助け合うピアサポートを活用すれば、大切な人間関係を損なうことなく療養に専念できます。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails
- DB：PostgreSQL（Neon）
- デプロイ先：Render
- 使用予定ライブラリ：
  ‐ Bootstrap
  - devise
  - turbo-rails
- スクリプト：
  - GASで定期的にHTTPリクエスト送信

### 10-2. 技術選定の理由

- なぜこの技術を使うのか：
ユーザーは主にメッセージを流す、拾う操作を繰り返し行います。このメイン操作のストレスをなくすため、非同期処理を用いトップページ内で完結するようにします。ページ遷移はログイン関連や拾ったメッセージ一覧に限定します。デリケートなメッセージを扱うため、HTTPリクエストによるメッセージ表示を阻止する意図もあります。

バックエンドにはActive Recordによる直感的なクエリ発行が可能なRailsを採用し、デプロイサービスにはRailsで幅広く利用されているRenderを選定しました。DBにはRenderが推奨しているPostgreSQLを使用します。PostgreSQLは複雑なクエリや多数のデータ型に対応した汎用性の高いDBMSです。今回は無料サービスとして運用するため、費用の発生しないNeonを利用します。また、Webサービスのスリープを防ぐためスクリプトで定期的に起動するようにします。

セキュリティ向上のため認証用gemのdeviseを使用します。
承認機能や通報機能のため、HTML/CSSでユーザー管理権限と管理画面を実装します。
- 今回チャレンジしたい点：
直感的なUIとアナログな体験の演出にこだわりたいと思います。
- 不安な点：
現状では収益モデルがない点です。まずは無料サービスとしてユーザー数を増やしながら、ユーザーがどのような困りごとを抱えているのかを分析し、収益モデルを検討します。
